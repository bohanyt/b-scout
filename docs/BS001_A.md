# Checkpoint A temporal oracle

This package provides fixture generation, a streamed native-time ledger, oracle verification and exact frame recovery. It implements BS-001 Checkpoint A only. It has no detector, production analyzer, packet writer, OCR or provider. B/C remain held for Control Tower review.

## Clean-checkout proof

With Git and Python >=3.11 installed, run from a clean checkout:

```powershell
python scripts/prove_bs001_a.py --work "$env:TEMP\bscout-a-proof-new"
```

On POSIX use a new temporary path, for example:

```sh
python scripts/prove_bs001_a.py --work /tmp/bscout-a-proof-new
```

The work directory must be new or empty and outside the repository. The script creates an isolated venv, downloads exact binary pins from PyPI without a cache, records wheel hashes, installs the package, regenerates both seed splits twice, verifies the media, runs bootstrap/runtime tests and separate-process resource probes, and writes `result.json` and `tests.txt`. Only pip uses the network. No system FFmpeg, user footage, old corpus, credentials or global dependency cache is needed. Bootstrap commands remain valid without runtime packages; media-dependent tests explicitly skip.

The executed platform/version, clean Git head, T1/T2/T3 hashes, every fixture, every skip and resources are recorded in the report. The script does not merge, dispatch CI, or claim independent acceptance. A report from a dirty checkout is visibly marked; acceptance evidence must come from the recorded clean tested head.

## CLI

Install in an external environment with `python -m pip install .`, then:

```sh
bscout --version
bscout --help
bscout fixtures generate --corpus corpus-v1 --out TEMP_MEDIA
bscout ledger TEMP_MEDIA/main60-s11.mp4 --out TEMP_LEDGER.jsonl
bscout oracle verify --corpus corpus-v1 --media TEMP_MEDIA --out TEMP_ORACLE
bscout recover TEMP_MEDIA/main60-s11.mp4 --ledger TEMP_LEDGER.jsonl --pts 1000 --out TEMP_FRAME.yuv
```

The recovery PTS must come from that actual ledger's native time base, rather than the generator schedule or FPS. The `.yuv` output concatenates unpadded native planes in ledger domain order. Existing files and source aliases are rejected. Failed/partial/unknown-time ledgers return exit code 2. Raw H.264 is deliberately diagnostic with null PTS; its ID/survival oracle passes but exact seek recovery is unavailable and explicitly skipped.

## Frozen truth and identity

[Spec](../src/bscout/corpora/corpus-v1/spec.json), [canonical annotations](../src/bscout/corpora/corpus-v1/annotations.json) and [T1 digests](../src/bscout/corpora/corpus-v1/digests.json) define corpus-v1. Dev seed is 11; held-out seed is 97, reserved for future B evaluation. A verifies both. Initial authoring identified and corrected overlapping 30 FPS panels before this first committed freeze; published truth must never be silently changed in place. Future truth changes require a new version or explicit CT-reviewed diff.

Serialization is sorted-key compact JSON, UTF-8, no NaN, one trailing LF. Schedules are explicit integers in 1/60000 seconds. Mapping is checked luma frame ID to generator index, followed by exact rational timing comparison. It never assumes decoded ordinal equals generator ordinal. The ID strip is `[0,0,384,32]`; 24 high-contrast 16 px cells encode a uint16 generator index and CRC32 low-byte check bits. B must exclude harness-only candidates from evaluation or use strip-free twins.

Known identity is `(source_sha256, selected_stream_index, raw_pts, same_pts_ordinal)`. The ordinal within duplicate PTS is counted in presentation traversal, including non-adjacent repeated PTS, with bounded SQLite page cache on temporary disk. Ledger ordinal is a traversal reference only. Origin is first presented decoded PTS; container start (microseconds), stream start and first PTS retain separate units and values. Raw PTS are never rewritten. Default edit-list handling is enabled and recorded. Missing/best-effort timestamps and last-frame duration remain unknown when unavailable. Non-monotonic/duplicate/missing timing becomes a diagnostic, with per-frame flags. VFR holds are not misreported as nominal-FPS gaps.

Nearest-representable timing rounds ties away from zero with absolute error <= half a container tick; exactly representable timestamps require equality. ID and PTS maps must both be monotonic bijections. Native digest domain v1 includes format, dimensions and plane storage layout plus only logical row bytes; allocator padding is excluded. RGB is not canonical. Unsupported native storage layouts fail explicitly. Lossless FFV1 is compared pixel-exactly against the generator's studio-range YUV420 planes with no color conversion.

## Survival and seek proof

Each event is independently omitted from the generator to create a counterfactual background. Across Y/U/V ROI samples, the verifier reports projected retained signal and normalized reconstruction error. Easy frames require projection >=0.5 and normalized RMSE <=0.5; challenge frames report survived/degraded. Zero counterfactual signal fails truth validation. These are fixture survival checks, not detector recall. Challenge scenes use synthetic checker panels and motion, not game assets or OCR text.

Recovery seeks backward to a decodable point strictly preceding the target's prior keyframe, then decodes in presentation order to exact raw PTS and duplicate ordinal and compares its native digest. Missing identities fail. The oracle exercises every annotated frame, first/last/pre-keyframe and random samples. Persistent HUD spans the clip, so this corpus's recovery set covers every frame in each known-timing fixture. CFR H.264 checks actual B frames and keyframe positions for the 2-second GOP. MP4 uses edit-list defaults and B-frame delay. 60000/1001, VFR and non-zero origin exercise separate container timing behavior. Audio-before-video uses 854x480 to exercise stream selection and plane padding.

The decoder checks corrupt packets **and corrupt decoded frames**, including concealed FFmpeg errors. It also checks a known container frame count against decoded count. This cannot guarantee detection of all silent bitstream corruption without independent truth; the fixture oracle supplies that additional check. Unsupported inputs produce failure trailers with reasons. Sources are hashed before/after ledger/oracle reads. Real duplicate and non-monotonic timing are deferred; their counter/identity logic is injected and tested.

## Resources and digest tiers

The ledger streams each row and stores PTS counts on disk. Reports contain process lifetime peak RSS including native allocations (`GetProcessMemoryInfo.PeakWorkingSetSize` on Windows, `ru_maxrss` elsewhere), elapsed time and exact output bytes. Resource probes run in separate processes with 1,000 and 20,000 real PyAV frames and streamed rows; growth must be below 32 MiB. This proves the ledger row/counter path, not high-resolution footage throughput. Oracle evaluation keeps metadata for the deliberately small frozen fixture, not decoded video arrays.

T1 covers semantic spec/annotation/schedule truth. T2 covers native decoded planes for identical encoded bytes. T3 covers encoded files and ledger bytes with toolchain context. Container `+bitexact` removes random Matroska identifiers; a second complete encode verifies same-toolchain encoded bytes. Ledgers include elapsed/RSS and therefore their byte hashes intentionally vary. T3 variation is not automatically a T1/T2 truth failure.

## Dependency provenance and later packaging

Exact runtime pins are [requirements-runtime.txt](../requirements-runtime.txt); complete proof pins are [requirements-proof.txt](../requirements-proof.txt). [PyPI's PyAV release](https://pypi.org/project/av/18.1.0/) supplies the binary wheel. PyAV metadata declares BSD-3-Clause; NumPy is BSD-3-Clause. Wheel names, hashes and native library configurations/license strings are recorded by proof. Hardware decode is disabled, even if the vendor build exposes hardware codecs.

The inspected Windows wheel includes libx264 core 165 and libx265 DLLs. Its FFmpeg libraries report LGPL version 3 or later, while [FFmpeg's licensing documentation](https://ffmpeg.org/legal.html) identifies libx264 as a GPL library. The fixture encoder is a development requirement, not a decision to distribute that binary stack in a desktop release. No licensing/distribution posture changes here; CT/user must resolve packaging at BS-004 using these provenance facts. Encoder logs retain the actual x264 build/settings string.

Untested: Linux/macOS execution and T2 portability, Windows symlink creation when denied by privilege, private footage, high-resolution throughput, HDR/10-bit/rotation/SAR/interlacing, changing formats, timestamp wrap, NLE interpretation, other Python versions and all B/C/later work. Actual proof-specific skips and limitations are in its machine-readable report.
