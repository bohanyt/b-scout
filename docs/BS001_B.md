# BS-001 Checkpoint B regional baseline

This is an experimental classical-CV baseline with native retained evidence. It does not provide a production packet or desktop workflow. The accepted [A contract](BS001_A.md) governs source identity and exact recovery.

## Commands

Use Python 3.11.9 and the exact runtime/proof pins. Environments and generated media stay outside the checkout.

```powershell
python scripts/prove_bs001_b.py --work "$env:TEMP\bscout-b-proof-new"
```

The default clean-checkout entrypoint installs fresh no-cache pinned wheels, runs the complete A proof, regenerates both seed splits twice, scans every presented frame, independently checks generator IDs/native timing, verifies actual retained asset bytes against independently decoded source, evaluates frozen B configuration on both splits, runs tests/bootstrap and separate B resource processes. Full fixture mappings are deterministic compressed JSON archives; the main report inventories their bytes and hashes. No GitHub Actions execution is part of these commands.

```powershell
bscout candidates SYNTHETIC_VIDEO --out NEW_EXTERNAL_DIRECTORY --config tests/baselines/regional-config.json
python scripts/tune_bs001_b.py --media EXTERNAL_CORPUS_DIRECTORY --out NEW_EXTERNAL_DEV_TUNING_JSON
```

The tuning entrypoint selects only dev annotations. It measures candidate localization and noise without claiming retained evidence. The final proof requires a dev-only freeze before any held-out B scan, checks its canonical configuration hash, records the freeze file SHA, and checks installed source bytes and checkout stability. `--split dev --skip-full-a` is an explicitly narrower development command; `--skip-full-a` records omitted full A proof rather than presenting it as executed.

## Signals and intervals

Every native yuv420p presentation frame receives 2x2 luma box means and native U/V samples. Eight analysis samples form a 16-source-pixel tile; edge tiles are clipped with weighted means. Each signal row preserves native PTS/time-base/identity and raw per-tile luma mean, bright occupancy, consecutive luma delta, stable-reference luma/chroma delta, activity and replacement decisions. The detector receives no annotation, event label, generator ID or harness geometry.

Per-frame diagnostic feature values are serialized to four decimal places; candidate trigger payloads preserve the full computed float values. Native source identities and retained plane bytes remain exact.

Inactive tile references update by an explicit EMA. Active references stay fixed to preserve accumulated changes. Foreground structure, short changes and accumulated luma/chroma changes are independent triggers. Content signature changes close an interval and start another; an observed absence followed by reappearance has a new tile occurrence. HUD tiles remain active analysis regions and overlapping changes remain eligible.

The baseline also emits fixed 1/3/5-frame structural inspection windows within active bright/chroma runs. These observations share their parent visual occurrence and do not assert a new appearance or content boundary. They preserve localized evidence inside an unchanged panel. Both the full state intervals and observations remain in diagnostics; there is no minimum event duration or candidate-count cap.

Frozen corpus-v1 has visually identical contiguous labels (`first`/`one_b_phase`, and 30-FPS `reopen`/`five_key_straddle`). No pixel signal identifies those internal annotation boundaries. The evaluation reports state-interval recall separately from structural-observation coverage, plus shared matches. It does not claim the detector recovered an invisible semantic boundary. Genuine A-to-B replacements and close/reopen gaps have separate state-interval tests and mappings.

## Exact evidence and unsupported inputs

One actual A validation creates a VT. A second full scan uses the same resolved immutable decoder configuration and checks every frame's PTS/time-base/key/representation/native digest against its VT position before L0. Evidence positions are deduplicated in SQLite; each candidate selects its first and last observed positions. Recovery uses genuine accepted A backward seek/decode-forward with contiguous VT alignment.

Retained assets include padding-free native YUV planes, a native-luma PGM and a lossless native-luma PNG for inspection. PNG/PGM are previews; the source/configuration-bound native-plane digest remains canonical. The proof verifies actual native asset bytes/domain hash and pixel-exact previews against an independent post-scan decode. Full-frame assets preserve context around small tile candidates.

Only even-sized native 8-bit yuv420p is supported by this B signal baseline. Unknown PTS, unsafe/incomplete validation, representation changes, decode errors and budgets yield explicit partial/failed B diagnostics. Raw H264 fixtures are scanned for candidate diagnostics but cannot retain exact timed evidence through A; these are reported separately with null timing/rates and unavailable evidence, never counted as timed evidence success. A remains capable of its separately documented digest domains.

## Evaluation policy

Evaluation uses the checked generator-ID channel, never decoded ordinal alone. Candidate/evidence must overlap truth spatially, retain a verified representative inside both intervals, and have boundaries within one generator frame. At least 80% of the smaller region and 25% of the candidate must overlap truth. Whole-frame and effectively full-clip candidates are rejected.

The frozen synthetic evaluation policy includes one bounded exception: **a spatially localized persistent HUD may have a full-clip track when its signals and exact evidence are verified**. The freeze records this authorization. The evaluator applies it only to the frozen `persistent_hud` truth, below half the source area, with required spatial overlap and verified evidence. Other full-clip candidates remain rejected.

Report candidate and usable-evidence coverage, state versus inspection recall, every easy/challenge miss, all unmatched/noisy candidate IDs, harness-only candidates separately, native-duration rates, one-frame and full duration distributions, temporal overreach, exact identities/assets, decoded/scanned counts and resources. Harness-only observations are removed from detector performance/noise metrics solely by the evaluator; the detector never masks the strip. This is synthetic localized evidence coverage, not production text recognition or universal recall.

## Resources and failure behavior

RAM contains bounded analysis planes and tile state, no full-video decoded history. Live tile count and analysis pixel budgets are explicit. Candidate/reference metadata is streamed to JSONL/SQLite with a bounded page cache. The metadata spool budget includes live VT storage; retained assets have a separate byte budget. Budget checks occur per frame, per 128 candidate records and per evidence row. A staging quantum can exceed the threshold before the explicit stop; its size is bounded by configured frame/tile geometry. Final diagnostics have a separate bounded reserve. Exact measured peak/final bytes and process-lifetime RSS including native allocations are recorded.

Per-fixture RSS in the full proof is cumulative for its shared worker and includes earlier evaluation/report materialization. Separate-process B stress measures streaming L0 state at fixed geometry. Structural inspection windows often select every presented position, with assets deduplicated by position; long clips can exhaust the explicit asset budget and return partial diagnostics.

A's optional validation storage ceiling interrupts decoding with an incomplete traversal and cannot mint complete prefix authority. Its default behavior and identity/recovery checks remain unchanged. VT storage is removed before B output publication; only owned temporary/output directories are cleaned. Final outputs are new directories with explicit diagnostics, with source verification before publication. There is no production packet, READY marker, schema migration, cancellation protocol, OCR/model/provider, UI or external media upload.

Historical runtime reports are retained in the owner private workspace. Minimal synthetic proof inputs remain in `tests/baselines/`; generated footage and full assets are not committed.
